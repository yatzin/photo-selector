# Video Editing tool: design

## Intent

Users send phone photos and videos to the Video Editing Inbox (done). This tool
turns them into finished videos inside the app: pick clips, arrange them on a
timeline, trim them, add text and transitions, export a new video. It should
feel like a polished consumer editor (iPhone / CapCut class), not a form.

## Goals

- Multiple projects per user. Open, create, rename, delete.
- Import clips from the Inbox into a project; see them in a small file tree on the left.
- Drag clips onto a timeline, trim either edge with drag handles (live frame preview), reorder, split.
- Preview with play, pause and scrub, instant while editing.
- Export the timeline to an MP4 on the server.
- Projects are plain folders and files, so they can be copied and used as templates later.

## Non-goals (this design covers slice 1 only)

- Text overlays, transitions, audio, animations: later slices (2 text, 3 transitions, 4 audio). The file format and timeline model must leave room for them (a `tracks` list, per-clip `transitionIn`), but nothing for them is built now.
- Collaboration, real-time multi-user editing of one project.
- Mobile layout. Desktop browser first.

## Anti-goals

- A form-style UI with number inputs for trim times.
- Re-encoding while editing. Preview must never wait on ffmpeg.
- Losing a user's work: autosave, and export never overwrites a previous output.

## Layout of a project

`Projects/<user>/<project>/` (user folder name from `tempFolderName`; project folder name is the project name, cleaned the same way):

```
project.json   the timeline: tracks, clips, trims, order, settings (the only file the editor reads and writes)
assets/        clips imported from the Inbox (copied in)
output/        the latest rendered video and .export-state.json (see Decisions)
config/        export.json: resolution, fps, codec presets (reusable when templating)
```

`project.json` is versioned (`"version": 3`) and holds `tracks`, each
`{ id, magnetic?, clips }`, with clips as `{ id, asset, in, out, start, transform?, muted? }`
(`in`/`out` are seconds into the asset; `start` is the timeline position, on
every track). A version 2 file (base clips without `start`, laid end to end)
and a version 1 file (one flat `clips` list, read onto the base track `t1`)
are read as version 3 with their base clips end to end from 0, the same
timeline as before, and saved as version 3 from then on.
Writes are atomic (temp file then rename).

## Decisions made with the user

- Files, not SQL, for project state and configuration (templating later).
- Subfolders per project for what's being built, outputs and configuration.
- Server-side ffmpeg export; slice order: skeleton, text, transitions, audio.

## Decisions made by me (change any of these)

- Import copies the file into `assets/` and leaves the Inbox original, so a project is self-contained. Copy, not move, not link.
- Preview plays the asset files directly in the browser (HTML5 video via the existing media route), no proxy files. Formats the browser can't play (some HEVC/MOV) fall back to a generated proxy later, not in slice 1.
- Timeline built in React with pointer events, no editor library. Matches the existing shadcn look.
- Export runs as a background job on the server with progress shown in the UI. Cuts only in slice 1: concat of trimmed clips, normalised to the project resolution and fps (default 1080p, 30 fps).
- Images on the timeline are supported. An image asset has `kind: "image"`; its clip starts at 5 s (`DEFAULT_IMAGE`) and stretches from 0.2 s to 10 minutes (`MAX_IMAGE`), with `in` always 0. Export loops the converted preview still for the clip's length with silence; the browser preview shows it as an image on the clock.
- An imported asset records its Inbox path as `source`. Importing the same Inbox file again (Import button or dragging it onto the timeline) reuses that asset while its file is still in `assets/`, instead of copying it again.
- Autosave to `project.json` after each edit, debounced.
- Routes: `/tools/video-editing` (project list), `/tools/video-editing/<project>` (editor). Sidebar "Video Editing" label links to the list.
- Access: a user sees and edits only their own `Projects/<user>/` folder in this tool.
- ~~`project.json` in v1 holds one flat `clips` list.~~ Superseded: version 2 has `tracks` (layers), up to 4 (`MAX_TRACKS`). ~~Track 0 is the base: magnetic, clips end to end, edits ripple.~~ (Superseded by "Free placement on every track" below.) Tracks 1 to 3 are overlays: clips sit at their own `start`, gaps allowed, no overlaps (a drop or move slides to the next free slot after the clip it would overlap). A higher track draws over a lower one, opaque and full frame (letterboxed; position, scale and crop came later as the clip transform, opacity not yet); every unmuted track's audio is mixed. The timeline's length is the latest clip end on any track. Undo covers `{ tracks }`, mute toggles included. `transitionIn` still isn't there.
- Export with layers: the base track is concatenated as before (a single-track project exports exactly as it did), laid over a black canvas the timeline's length, and each overlay clip, shifted to its start, overlaid in track order with `enable=between(t,start,end)`. Audio mixes the base track and each unmuted overlay clip (delayed with `adelay`) over silence the timeline's length (`amix`, `normalize=0`).
- Preview with layers: each track has its own pair of video elements (8 at most); all play from one clock and are heard (the preview now shows every one with a clip; see "Preview with all layers"). The lowest track playing a healthy video drives the clock; other tracks are re-seeked if they drift more than 0.3 s.
- Clip transform: a clip may carry `transform: { x, y, scale, cropTop, cropBottom, cropLeft?, cropRight? }` (absent means none). `cropLeft`/`cropRight` cut fractions of the scaled width from the left and right with the same limits as top and bottom (absent is 0, and a zero one isn't stored, so older transforms keep their shape). The picture is fit inside the canvas (letterbox), `scale` multiplies that size (0.1 to 5), `x`/`y` move its centre from the canvas centre as fractions of the canvas width and height (at most 2 either way), and `cropTop`/`cropBottom` cut fractions of the scaled height from the top and bottom (each up to 0.9, together up to 0.95) without moving what's left. `lib/video/transform.ts` holds the shared math (`clipRect`, gesture and snap helpers); parse and merge reject a transform outside the limits, the UI clamps. Split, move, trim and undo keep it; the identity is stored as no field. The export fingerprint includes it. A clip with no transform still fills the canvas letterboxed in black, opaque, as before; a transformed one covers only its visible strip.
- Preview with all layers: every track with a clip at the playhead is shown, stacked in track order, each placed by its transform (absolute position in percent of the canvas, the crop as `clip-path: inset`), over a black canvas the project's shape. Selection is shared between the canvas and the timeline; a drag shows a draft and commits one undo step on release. A transform-only edit doesn't re-seek the players.
- Export with transforms: a project where no clip has a transform and the base track runs back to back from 0 builds exactly the graph it always did. Otherwise (a transform, or a gap on the base track) every clip, base track included, is overlaid on the black canvas in track order with its own `enable` window: a transformed clip is fit, scaled to even sizes, cropped and placed with overlay `x`/`y` expressions that mirror `clipRect`; an untransformed one is letterboxed to the full canvas as before. Audio is each heard clip's sound delayed to its start, over silence.
- Free placement on every track (file version 3): the base track is no longer magnetic. Every clip has its own `start`, gaps are allowed on every track, and removing, trimming, moving or splitting a clip never moves another. Overlaps on a track are still refused: a drop or move slides to the next free slot, and a trim stops at the neighbour. A gap is black and silent in the preview (the player's wall clock carries the playhead across it when no lane has a healthy video) and in the export. `freeTrackFor` finds the lowest track with room for a span.
- Deleting a media item: `deleteAssetAction` removes the asset from `project.json`, every clip that uses it on every track (the stored project decides, not the client), and its file in `assets/` (best effort, a regular file inside `assets/` only). It's refused while the project exports. The client applies the pure `removeAsset` to its copy and resets undo history. The next export renders afresh because the clips changed.
- Snapping on the canvas: a move snaps the visible strip's edges or centre, a corner the dragged corner, and a crop handle the cropped edge to the canvas edges and its vertical and horizontal centre lines (6 screen px). Every line the result sits on is drawn, so a full-width picture shows the centre line with the edges. Alt held (live, also pressed or released without moving) turns it off; a hint pill under the canvas (inside at the bottom when there's no room) says so during a drag.
- The preview's surround is light gray (neutral-200) in the light theme and a darker gray (neutral-700) in the dark theme, not near-black; the canvas stays black. The selection frame is sky with a dark halo and the handles white with a dark border, to read on both.
- Dropping media on the player: the clip starts at the playhead on `freeTrackFor`'s track (a new layer below MAX_TRACKS), never sliding; with none free it's refused with a toast. It's one undo step and the new clip is selected. An Inbox file is imported first and placed in the project as it is then.
- Deleting media from the editor: Project media rows have a right-click menu and Delete on the focused row; the confirm counts the clips from the live timeline. On success the client resets undo history to the new state (an older step could hold clips of the gone asset, which the server would refuse to save).
- Timeline width (supersedes a fixed 240 px pad over a 600 px minimum): content end plus 240 px, at least the viewport, and while a clip move, trim or file drag runs, 10 s past the dragged end. That extension is drag state only, never saved. It shrinks with the content; the browser clamps the scroll and the player clamps the playhead.
- Auto-pan: any timeline drag (move, trim, scrub, file ghost) within 48 px of the viewport's left or right edge scrolls it, up to 900 px/s, in a rAF loop; the dragged item is placed from the current scroll each frame (pointer travel plus scroll travel since the press).
- Snap on V1 (`Track.magnetic`, base track only, optional in version 3, default off): a role=checkbox magnet button in V1's header. Ticking it packs V1 end to end in start order with the flag as one undo step; while on, add/move/trim/split/delete/removeAsset repack V1 (a drop or move goes in at the slot given by how many V1 clips have their midpoint before the drop time, trims keep the clip's start and ripple the rest, a pack that would pass MAX_TIMELINE refuses the edit). Unticking only clears the flag. parseProject strips it from overlays, refuses a non-boolean and repacks a snapped base instead of refusing its gaps. The export fingerprint ignores it (a pack changes starts anyway). In the timeline the drop/drag target on a snapped V1 is an insertion line chosen by the pointer time, not a ghost.
- Dense layers: with 3 or 4 tracks rows are 40 px instead of 80, times a vertical zoom of 0.6 to 2 kept in localStorage (`ps.video.rowZoom`); short rows put the header's label and buttons side by side in a wider column. The zoom now scales the rows at every layer count (the 40 px default from 3 layers stays); the slider still shows from 3 layers.
- Layer labels: the row headers read 1 to 4 (1 is the base at the bottom), not V1 to V4; titles and aria labels say "Layer 1" and so on, and the Snap box's title says it applies to layer 1.
- Timeline mouse wheel (a non-passive native listener, so it can keep the page from scrolling; the page keeps the wheel only when the timeline can't use it, and a drag in progress is left alone). Deltas are normalised to pixels (lines x40, pages x the viewport), and a 100 px notch zooms 8% (at most three notches an event). Over the layer numbers: the vertical zoom, in step with the slider. Over the ruler, or Ctrl/Cmd anywhere over the clips: the horizontal zoom (20 to 200 px/s, in step with the Zoom slider; the wheel may land between its whole steps), anchored so the time under the pointer stays under it (`zoomAround`, applied in a layout effect once the new zoom has rendered). Over the clips: deltaY plus deltaX scroll sideways; Shift scrolls up and down when the rows overflow.
- Per-clip mute replaces the layer mute: `Clip.muted` (true or absent) and no `Track.muted`. parseProject reads an older file's `track.muted: true` as `muted: true` on each of that track's clips; mergeClientProject strips a client's track `muted` (so a stale tab can't mute a whole layer) and keeps clip mutes. `setClipMuted` is one undo step; split gives both halves the flag, moves and trims keep it, and the export fingerprint includes it. The timeline shows a speaker button on each video clip with sound (hover, focus or selection, always while muted; its press never drags or selects), and **M** toggles the selected clip. The preview sets each video element's `muted` from the clip it holds (no re-seek on a toggle). The export gives a muted clip silence exactly where a muted layer's clips had it, so a project with nothing muted builds the same graph as before.
- Waveforms: the server computes peaks (`lib/video/peaks-server.ts`): ffmpeg decodes the asset's sound to mono 8 kHz s16le on stdout (args array, no shell, 120 s timeout), binned as it streams (max |sample| of every 80, scaled 0..255: 100 peaks a second). They're cached beside the asset as `assets/.<file>.peaks` (version byte, rate as uint16 LE, peaks), written temp-then-rename, made on the first request and reused after (asset files never change); one decode per file at a time and at most 2 at once. Deleting a media item deletes its peaks file. `GET /api/video-projects/<project>/peaks/<asset>` (session required, plain names, a video asset with sound in the stored project, else 404) returns the bytes with `Cache-Control: private, max-age=31536000, immutable` (asset ids are never reused) and `X-Peaks-Rate: 100`. The client fetches each asset's peaks once a page, only for clips on the timeline and only while waveforms are on, and draws each clip's [in, out) on a canvas over its thumbnail and a dark scrim (`waveformBars`: one bar per 2 px, the loudest bin each covers), redrawn on zoom, trim and row height, not during playback; a clip wider than 4096 device px draws only the part in view. A toolbar button shows or hides them (`ps.video.waveforms`, on by default).
- Timeline snapping across layers: a clip move snaps its start or end, a trim the dragged edge, and a file's ghost its start or end, to 0, the playhead and both edges of every other clip on every layer (8 screen px; `snapEdges` in `lib/video/timeline-math.ts`). A 2 px fuchsia guide spans the rows at the snapped time while it holds (none when the slide past a neighbour or a trim limit took the edge off it). Alt held turns it off, tracked live during a pointer drag (pointer altKey plus Alt keydown/keyup, whose browser default is prevented) and from each dragover's altKey for a file. A pill at the top centre of the timeline view, under the ruler and outside the scrolled content ("Hold Alt to turn snapping off", "Snapping off" while held, `aria-hidden`, no pointer events) shows during a snapping drag. A move or drop onto a snapped V1 uses its insertion line and shows neither; a right-edge trim on a snapped V1 snaps to the other layers' edges only (its own clips ride along); a left-edge trim there doesn't snap at all (no guide, no hint), since its draft is only a stand-in until the pack on release.
- Snapped V1, left-edge trim: while dragging, the clip shows the plain trim (`leftTrimDraft`: the start moves with the edge, the right edge and every other clip stay, no pack; the draft may reach over the previous clip, down to time 0, the source's start and MIN_CLIP, and for an image up to MAX_IMAGE). The draft doesn't snap to any layer and shows no guide or Alt hint. Release commits `trimClip` with the draft's clamped edge, which packs V1 as before: one undo step, the same end result. Reaching over the previous clip is what makes expanding to the left possible at all on a packed layer (its previous clip's end is the clip's own start). The right edge keeps its live ripple.
- Rotation and flips: `Transform` has `rotation?` (degrees clockwise, normalised to (-180, 180], absent is 0) and `flipH?`/`flipV?` (absent is false); parse and merge refuse anything else, zero and false aren't stored, the identity check, the fingerprint, split, move and undo carry them. The canonical order, documented in `lib/video/transform.ts`: fit, scale, flip (about the content centre), crop (screen-axis fractions, so a flipped picture is cropped where the user sees it), rotate about the content centre (the centre of the whole scaled picture, so a crop never moves the pivot), place. `clipRect` stays unturned; `rotatedCorners`, `rotatedBounds` and `containsPoint` turn it. The preview gives the picture element `rotate() scale(±1, ±1)` about its own centre (the content centre) and a clip-path inset with the flipped sides swapped (clip-path is cut before the element's transform), equivalent to the nested flip/crop/rotate boxes. Selection, hit-testing and handles follow the turn: drags are taken in the clip's own axes, a corner scales about the opposite corner where it shows, a turned clip's move snaps its bounding box, and its corner and crop drags don't snap. A white Rotate button floats about 22 px out from the frame's top right (along the frame's axes): drag to turn by the pointer's angle round the centre, snapping to 15 degree steps within 3 degrees unless Alt is held, with an angle readout, Esc to cancel, one undo step; double-click straightens; Left/Right turn 1 degree (Shift 15), grouped. Two flip buttons float at the top left (`aria-pressed`, each click one undo step): the left one (`FlipHorizontal2` icon) flips vertically (`flipV`) and the right one (`FlipVertical2` icon) flips horizontally (`flipH`); icons and places are as before, only the actions were swapped. The floating buttons are kept inside the pane's visible area. Reset clears rotation and flips too. Export: a flip-only clip adds `hflip`/`vflip` after the scale (placement unchanged); a turned clip goes RGBA, flips, makes the cropped sides transparent in place with `drawbox ... replace=1` (the frame keeps its full scaled size, so its centre is the content centre; this stands in for crop-then-pad, which can't know the pre-crop size), `rotate=<rad>:ow=rotw:oh=roth:c=black@0`, `yuva420p`, and is overlaid at `(W-w)/2 + x*W`, `(H-h)/2 + y*H`. Projects without flips or rotation build the same graphs as before.
- Play/Pause sits in the middle of the timeline toolbar (a `1fr auto 1fr` grid: edit tools left, Play/Pause centre, waveforms and zoom right), not over the preview. Space, its guards, titles and labels are unchanged; it's disabled with no clips.
- Clip context menu (`components/video/clip-menu.tsx`): right click on a clip block (or the menu key on a focused one) prevents the browser menu, selects the clip and opens a portalled `role="menu"` at the pointer, moved left or up to stay 8 px inside the window. Not during a pointer drag or trim. Focus goes to the first enabled item; ArrowUp/Down wrap, Home/End, Enter/Space run an item; Escape, Tab, a press outside, any scroll, a resize or window blur closes it, and focus goes back to the clip. The timeline builds the items list per clip (`menuItems`), so a clip kind adds its own: Split at playhead (S; disabled unless the playhead is at least MIN_CLIP inside that clip, splits that clip), Delete (Delete), Mute/Unmute (M; video with sound only), Edit length... (images). Each is one undo step. Right click on empty timeline space keeps the browser's menu.
- Edit length dialog (`components/video/edit-length-dialog.tsx`, the ui Dialog): Start, End and Length in seconds (2 decimals shown; a field you don't touch keeps its exact value). Length keeps Start and moves End; End changes Length; Start moves the clip and keeps Length. Inline messages: not a number, Start below 0, End not after Start, Length under MIN_CLIP (0.2 s, the model's clip minimum, not 0.1, since parseProject refuses shorter images), plus `setClipTiming`'s own refusal. Apply is disabled while invalid, Enter applies, Esc cancels, Apply is one undo step. "When it overlaps other media" (native select): Push later media (default) or Overwrite media; on a snapped V1 Start is read-only, the select is disabled with a note, and the length ripples. `setClipTiming(p, clipId, { start, length }, mode, newId)` in `lib/video/clip-timing.ts` returns `{ ok, project }` or `{ ok: false, error }` and touches only the clip's layer. Push: the clips that started at or after the clip's old start and end after its new start all move right by the least that clears the new range (gaps kept, nothing moves left); a new range over an earlier clip is refused. Overwrite: overlapped clips are tail-trimmed, head-trimmed (a video's in moves so playback stays continuous), split around the range (the right piece gets a new id, the transform and the mute) or removed; a leftover under MIN_CLIP goes. Anything past MAX_TIMELINE, an image over MAX_IMAGE or a video past its source is refused.
- Text clips (`lib/video/text.ts`): a clip with `text: { content, color, orientation }` and `asset: ""` (no media). Optional field, so project.json stays version 3 and old projects parse unchanged. Content is 1 to 500 characters and not only whitespace (CRLF stored as LF), colour `#rrggbb` (stored lower case), orientation `horizontal` or `vertical`; parse refuses a text clip with an asset or bad text, drops a mute on one, and mergeClientProject skips the asset check for it. It times like an image (in 0, out = length, MIN_CLIP to MAX_IMAGE, no source limit) everywhere: add (`addTextClip`), trim, the snapped-V1 left-trim draft, split (both halves keep the text), move, Edit length and its overwrite/push. `setClipText` is one undo step; `isStill` (image or text) replaces the image checks in the player, preview and export.
- Text layout, shared by preview and export (documented in `lib/video/text.ts` and `lib/video/transform.ts`): one bundled monospaced font, Geist Mono Bold (`public/fonts/GeistMono-Bold.ttf`, SIL OFL 1.1, licence beside it), so the box is computable without measuring: font size a tenth of the canvas height (108 px on 1080p) times the transform's scale; box = longest line x 0.6 + 0.5 padding wide, lines x 1.3 + 0.5 tall (font sizes); each line centred across the box, its baseline 1.005 (the font's ascent) into its 1.3 slot. Horizontal text breaks only at newlines; vertical puts one character a line (code points), a space or newline leaving an empty line. `clipRect` takes this box (`{ w, h }`) in place of an aspect and skips the fit, so the transform pipeline, handles, snapping and hit-testing are unchanged; an identity transform means centred at natural size (not full canvas). Glyphs the font lacks fall back to other fonts and may differ between preview and export.
- Text in the preview: an SVG (viewBox = the layout at 100 px) of `<text>` lines in the bundled font (`@font-face "PS Video Text"` in `globals.css`, `font-display: block`), `text-anchor="middle"`, `white-space: pre`, inside a box placed like an image (clip-path crop, rotate, flip). Double-click on the canvas (the selected clip first, else the topmost) or the timeline block, or the menu's Edit text..., opens the Edit text dialog (textarea, colour input, direction select; Apply or Ctrl/Cmd+Enter is one undo step, Esc cancels). The clip menu adds Edit length..., Edit text... and a Horizontal/Vertical `menuitemradio` pair with a check. The timeline block is violet with a Type icon and the text on one line; no thumbnail, waveform or mute.
- Add text (toolbar, Type icon): a 5 s white "Text" clip at the playhead, centred, selected, with Edit text open; one undo step for the insert. Target: the selected clip's layer; with nothing selected or a clip on a snapped V1 selected, the lowest layer above the base free at the playhead for 5 s, else a new layer, else the base (appended at its end when snapped, else at the playhead, slid clear).
- Text export: rasterise, not drawtext in the graph and not sharp. sharp's text (Pango) crops its output to the ink and its SVG renderer can't load a font file, so neither can match the preview's box. Each text clip is drawn by a separate one-frame ffmpeg run (`lib/video/text-raster-server.ts`): a transparent `color` canvas the size of the content box, one `drawtext` per line (`fontfile` = the bundled font copied beside line text files in a temp folder, so nothing needs filtergraph escaping; `expansion=none`; `x=(w-text_w)/2`; `y_align=baseline` at the layout's baseline; graph through `-/filter_complex <file>`). It's drawn at the first multiple of 20 px at or above the clip's font size on the canvas (box sizes are whole pixels then; capped so the PNG stays within 8192 px) and the export scales it to the exact box (even px) like an image (`textRaster`), then flips, crops and turns it with the image filters, keeping alpha (`yuva420p`). PNGs are keyed by font size and text, shared between clips, kept in an `ps-text-*` temp folder and removed with the job. Any text clip makes the export use the uniform graph; projects without text build byte-identical graphs. The fingerprint includes each clip's `text` (absent when none, so older fingerprints don't change) and leaves text clips out of the used assets.
- Editor accent: `--editor-accent` (and `--editor-accent-foreground`) in `globals.css` is primary in the light theme and a light sky (sky-300, dark text on it) in the dark theme, used for the playhead, the Snap box, the selected clip's outline and trim handles, ghosts, the insertion line, the add-a-layer drop zone, the resize bar's hover, the sliders and the Play button; the preview's selection frame and drop outline use it in dark mode only.
- `config/export.json` is written when a project is created, but export reads width, height and fps from `project.json`. The config file is kept for export templating later.
- Projects are keyed by the user's display-name folder (`Projects/<display name>/`), the same way User Temp Storage keys its folders.
- ~~Outputs are kept per export, never overwritten.~~ Superseded: `output/` keeps one copy. A successful export writes `output/.export-state.json` (`{ file, fingerprint, createdAt }`, the fingerprint a SHA-256 of what affects the video: size, fps, tracks and the used assets) and deletes every other file in `output/`; a failed one changes nothing. An export whose fingerprint matches a copy still there reuses it without running ffmpeg. Either way the browser downloads the copy from `/api/video-projects/<project>/download`.
- In the library, Video Editing Projects is read-only: no move, delete or rotate, and Move to Video Editing/Temp only copies from it. The editor owns those files.

## Constraints

- Next.js in this repo has breaking changes: read `node_modules/next/dist/docs/` before writing routes, actions or route handlers.
- Follow existing patterns: server actions in `lib/actions/`, `*-server.ts` for disk code, `resolveInside` for every user-supplied path, no clobbering writes.
- Feature work stays on `feat/video-editing`. Nothing is committed unless the user asks.
- ffmpeg path comes from `FFMPEG_PATH` as in `lib/thumbs-server.ts`.
